# テスト観点表

単体・結合テストのケース設計で漏れを防ぐための観点。該当しないものは理由を添えて除外する。

## 入力値

| 観点 | 例 |
|---|---|
| 必須 | null / 空文字 / 空白のみ |
| 長さ | 最小長・最大長・最大長+1 |
| 形式 | 許可文字・禁止文字（記号・全角・制御文字） |
| 範囲 | 最小値-1・最小値・最大値・最大値+1・0・負数 |
| 型 | 数値に文字列・不正な日付（結合テストでは 400 `malformed-request`） |

## 業務ルール

| 観点 | 例 |
|---|---|
| 一意性 | 未使用 / 使用済み / 自分自身の値のまま更新 |
| 存在 | 存在する ID / 存在しない ID / 削除済み |
| 状態遷移 | 許可された遷移 / 許可されない遷移 |
| 権限 | 権限あり / 権限なし（403）/ 未認証（401）/ 無効化された利用者 |

## 一覧・ページング

| 観点 | 例 |
|---|---|
| 件数 | 0 件 / 1 件 / ちょうど1ページ / ページ境界+1 |
| 並び順 | 既定の並び順・同値時の順序（id で一意になるか） |
| 範囲外 | 最終ページの次 / size の上限超過（400） |

## 時刻・同時実行

| 観点 | 例 |
|---|---|
| 時刻 | 作成日時・更新日時が `Clock` の値になる / 更新で作成日時が変わらない |
| 同時実行 | 事前チェックをすり抜けた一意制約違反が 409 になる |

## frontend

| 観点 | 例 |
|---|---|
| 表示 | 読込中 / 0 件 / データあり / エラー |
| 操作 | 送信・キャンセル・連打（送信中の無効化） |
| 入力検証 | API の制約と同じエラーが出る |
| ロール | ADMIN と VIEWER で操作部品の表示が変わる |
| 多言語 | ja / en で文言キーが解決される |
