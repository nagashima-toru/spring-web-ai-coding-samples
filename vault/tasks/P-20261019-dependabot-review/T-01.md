# T-01 Dependabot PR の AI 影響確認ワークフロー dependabot-review.yml を追加する

## 目的
Dependabot の PR を契機に claude-code-action で更新の影響を確認し、判定と根拠を PR にコメントして `ai-review:safe` / `ai-review:needs-human` のラベルを付けるワークフローを追加する。マージは行わない。

## 入力
- `vault/designs/D-20261013-dependabot-ai-merge.md`（「決定事項」表と「フェーズ1」節。読むだけで変更しない）
- `.github/workflows/ci.yml`（既存 CI。書き方（日本語のステップ名・`actions/checkout@v7`・`timeout-minutes`）の参考。変更しない）
- `.github/dependabot.yml`（maven・npm・github-actions の3エコシステムとグループ更新の設定。変更しない）

## 成果物
- `.github/workflows/dependabot-review.yml`（1ファイル。新規作成）

## 受け入れ基準
- YAML として読めて、トリガが `pull_request`（types: opened, synchronize, reopened）だけで、`pull_request_target` はリポジトリの `.github/` 配下のどこにも無い（`python3 -c "import yaml,sys;d=yaml.safe_load(open(sys.argv[1]));t=d.get('on',d.get(True));print(sorted(t), sorted(t['pull_request']['types']))" .github/workflows/dependabot-review.yml` の出力が `['pull_request'] ['opened', 'reopened', 'synchronize']`、かつ `grep -rn pull_request_target .github/` の出力が空）
- ワークフロー最上位の `permissions` が `{}` で、すべてのジョブの `if` が `github.event.pull_request.user.login == 'dependabot[bot]'` の条件を持ち、ジョブの `permissions` がちょうど `contents: read`・`pull-requests: write`・`issues: write` である（`python3 -c "import yaml,sys;d=yaml.safe_load(open(sys.argv[1]));print(d.get('permissions'), all('user.login ==' in j.get('if','') and 'dependabot[bot]' in j.get('if','') and j.get('permissions')=={'contents':'read','pull-requests':'write','issues':'write'} for j in d['jobs'].values()))" .github/workflows/dependabot-review.yml` の出力が `{} True`）
- id `claude` のステップが `anthropics/claude-code-action@v1` を使い、`continue-on-error: true` で、`claude_code_oauth_token` に `secrets.CLAUDE_CODE_OAUTH_TOKEN` を渡し、`anthropic_api_key` を持たず、`claude_args` に `Edit`・`Write`・`git push`・`gh pr merge` を含まない。`.github/` 配下に `anthropic_api_key` の記述が無い（`python3 -c "import yaml,sys;d=yaml.safe_load(open(sys.argv[1]));s={x.get('id'):x for j in d['jobs'].values() for x in j['steps']};c=s['claude'];w=c['with'];a=w.get('claude_args','');print(c['uses'], c.get('continue-on-error'), 'secrets.CLAUDE_CODE_OAUTH_TOKEN' in w['claude_code_oauth_token'], 'anthropic_api_key' in w, [t for t in ('Edit','Write','git push','gh pr merge') if t in a])" .github/workflows/dependabot-review.yml` の出力が `anthropics/claude-code-action@v1 True True False []`、かつ `grep -rn -i anthropic_api_key .github/` の出力が空）
- id `metadata` のステップが `dependabot/fetch-metadata@v2` を使い、`claude` ステップの `prompt` が `steps.metadata.outputs.update-type`・`steps.metadata.outputs.package-ecosystem`・`steps.metadata.outputs.dependency-names` を参照し、語「日本語」を含み、`claude_args` が `--json-schema` で `verdict`（`safe` / `needs-human`）と `summary` のスキーマを渡している（`python3 -c "import yaml,sys;d=yaml.safe_load(open(sys.argv[1]));s={x.get('id'):x for j in d['jobs'].values() for x in j['steps']};w=s['claude']['with'];a=w.get('claude_args','');print(s['metadata']['uses'], [k for k in ('update-type','package-ecosystem','dependency-names') if 'steps.metadata.outputs.'+k not in w['prompt']], '日本語' in w['prompt'], '--json-schema' in a and 'needs-human' in a and 'safe' in a and 'summary' in a)" .github/workflows/dependabot-review.yml` の出力が `dependabot/fetch-metadata@v2 [] True True`）
- id `decide` のステップの `run` を bash で実行すると、major は AI の判定に関係なく、判定が `safe` 以外（空を含む）の時も `label=ai-review:needs-human` を出し、patch・minor で判定が `safe` の時だけ `label=ai-review:safe` を出す（`python3 -c "import yaml,sys;d=yaml.safe_load(open(sys.argv[1]));print([x for j in d['jobs'].values() for x in j['steps'] if x.get('id')=='decide'][0]['run'])" .github/workflows/dependabot-review.yml | env UPDATE_TYPE=<更新種別> VERDICT=<判定> GITHUB_OUTPUT=/dev/stdout bash` を、`version-update:semver-major`/`safe` → `label=ai-review:needs-human`、`version-update:semver-minor`/`safe` → `label=ai-review:safe`、`version-update:semver-patch`/`needs-human` → `label=ai-review:needs-human`、`version-update:semver-minor`/空（`VERDICT=`）→ `label=ai-review:needs-human` の4通りで実行し、出力がそれぞれ一致する）

- `.github/` 配下で変わったファイルは追加したワークフローだけで、`.github/workflows/ci.yml` は変わっていない（worktree の中で `git diff --merge-base work/p-20261019-dependabot-review --name-only -- .github/` の出力がちょうど1行の `.github/workflows/dependabot-review.yml`）

## 決定済み
- 設計文書の「決定事項」表とフェーズ1の「決定済み」を正とする。以下はその具体化と、受け入れ基準の確認コマンドが前提にする形
- ファイル構成：ワークフロー名は任意（例 `Dependabot 影響確認`）。最上位に `permissions: {}` を書き、ジョブは1つ（名前は任意、例 `review`）。ジョブに `if: github.event.pull_request.user.login == 'dependabot[bot]'`・`runs-on: ubuntu-latest`・`timeout-minutes`（20 程度）・`permissions`（`contents: read`・`pull-requests: write`・`issues: write` の3つだけ。`id-token` や `contents: write` は付けない）を書く。ステップ名は ci.yml にならって日本語にする
- ステップの順と id（確認コマンドがこの id で引くので変えない）：(1) `actions/checkout@v7`（`persist-credentials: false`。id は不要） → (2) id `metadata`：`dependabot/fetch-metadata@v2` → (3) id `claude`：`anthropics/claude-code-action@v1` → (4) id `decide`：ラベルを決める → (5) id `label`：ラベル付与とコメント投稿
- `claude` ステップの `with`：`claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`、`github_token: ${{ github.token }}`（action の OIDC によるトークン取得を使わず `id-token: write` を不要にするため）、`allowed_bots: 'dependabot[bot]'`（起動者が bot だと action が既定で拒否するため）、`prompt`、`claude_args`。`anthropic_api_key` と `model` は書かない。ステップに `continue-on-error: true` を付け、ステップの `env` に `GH_TOKEN: ${{ github.token }}` を渡す（AI が `gh pr view` を使うため）。シークレットの登録手順は書かない（人が行う。フェーズ2で docs に書く）
- `claude_args` は `--allowedTools` で `Read,Grep,Glob,Bash(gh pr view:*),Bash(gh pr diff:*)` だけを許可し、`--json-schema` で `{"type":"object","properties":{"verdict":{"type":"string","enum":["safe","needs-human"]},"summary":{"type":"string"}},"required":["verdict","summary"]}` を渡す。`--disallowedTools` は書かない（確認コマンドは `claude_args` に `Edit`・`Write` の語が無いことを見るため）。コメント投稿は AI に許可せず、後続の `label` ステップが決定的に行う（設計の「読み取り系とコメント投稿に限る」の範囲内で、さらに絞る）
- 判定の受け取りは structured output（出力 `structured_output`）だけを使い、`$RUNNER_TEMP/verdict.json` の代替経路は実装しない。後続ステップでは `${{ fromJSON(steps.claude.outputs.structured_output || '{}').verdict }}` と `.summary` の形で env に受け取る（AI が失敗して出力が空でも式が評価エラーにならない）
- `prompt` は日本語で書き、「日本語」の語を含めて、コメント用の summary を日本語で書くよう指示する。プロンプトに渡す情報：PR 番号（`github.event.pull_request.number`）、`steps.metadata.outputs.update-type`・`steps.metadata.outputs.package-ecosystem`・`steps.metadata.outputs.dependency-names`・`previous-version`・`new-version`。指示する手順：`gh pr view <番号>` で PR 本文（Dependabot が書くリリースノート・変更履歴）を読む、`gh pr diff <番号>` で変更を読む、Grep・Glob・Read でリポジトリ内の使用箇所を探す。summary には「使用箇所」「破壊的変更の有無」「リリースノートの要点」を含めさせる。破壊的変更の可能性がある・使用箇所への影響が判断できない時は `needs-human` にさせる
- `decide` ステップ：`if: always()`。`env` に `UPDATE_TYPE: ${{ steps.metadata.outputs.update-type }}` と `VERDICT`（上の fromJSON の式）を受け取り、`run` は既定を `ai-review:needs-human` とし、`VERDICT` が `safe` かつ `UPDATE_TYPE` が `version-update:semver-major` でない時だけ `ai-review:safe` にして、`echo "label=<ラベル>" >> "$GITHUB_OUTPUT"` の1行だけを出力する。`run` の中では `gh` などの外部コマンドを呼ばず、シェルの組み込み（`[`・`echo`）だけで書く（受け入れ基準でこの `run` をそのまま手元の bash で実行するため）。`UPDATE_TYPE` が空・想定外の値で `VERDICT` が `safe` の時は safe でよい（フェーズ2 の auto-merge は種別を別に確かめる）
- `label` ステップ：`if: always()`。`env` に `GH_TOKEN: ${{ github.token }}`・PR 番号・`steps.decide.outputs.label`・更新種別・依存名・`SUMMARY`（fromJSON の式で `structured_output` の `.summary`）を受け取る。`run` で `gh label create ai-review:safe --force --color <任意>` と `gh label create ai-review:needs-human --force --color <任意>` を実行し、`gh pr edit` で既存の `ai-review:` ラベル2つを外してから `--add-label` で決めたラベルを付け、コメント本文を `$RUNNER_TEMP` 配下のファイルに書いて `gh pr comment <番号> --body-file <ファイル>` で投稿する
- コメント本文（日本語）：見出し（例「AI による依存更新の影響確認」）、判定ラベル、更新種別、依存名、summary。`SUMMARY` が空の時は「AI の判定を取得できなかった（利用枠の上限などで AI のステップが失敗した可能性がある）。needs-human として扱う」旨を書く。major の時は「major の更新は AI の判定に関係なく人が確認する」旨を書く。このフェーズではマージしない旨を書いてもよい。再実行時に前回のコメントを更新するか新規に足すかは問わない（新規追加でよい）
- スクリプトインジェクション対策：AI の出力・PR 由来の値（依存名・summary など）を `run:` の中に `${{ }}` で直接埋め込まず、必ず `env` 経由でシェル変数として使う
- `gh pr edit --remove-label` は付いていないラベルを外そうとしても失敗しうるので、`|| true` を付けるなどして後続のラベル付与とコメントが止まらないようにする（書き方は任意）
- `on:` は `pull_request:` の下に `types: [opened, synchronize, reopened]` だけを書き、`branches` などの絞り込みは書かない。`workflow_dispatch` も付けない（確認コマンドがトリガのキーを `['pull_request']` ちょうどで見るため）
- PyYAML は計画作成時に 6.0.1 があることを確認済み。actionlint はこの環境に無いので受け入れ基準に使わない（creator が手元で使えるなら追加で実行してよいが、基準には含めない）。`import yaml` が失敗する環境では、構文だけは `ruby -ryaml -e 'YAML.load_file(ARGV[0])' .github/workflows/dependabot-review.yml`（終了コード0）で確かめられるが、受け入れ基準1〜6の構造の検査の代わりにはならないので、その時は blocked にして question に書く
- 受け入れ基準7の `git diff --merge-base` は creator・verifier の worktree の中で実行する（計画ブランチ上では空になる）。タスク票の「進捗」への追記は `-- .github/` で絞っているので出力に出ない
- 実際の Dependabot PR（#11 など）での動作確認は求めない。`.github/dependabot.yml` と `.github/workflows/ci.yml` と設計文書は変更しない
