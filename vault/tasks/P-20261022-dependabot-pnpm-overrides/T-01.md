# T-01 frontend/package.json の packageManager で pnpm を 9.15.9 に固定する

## 目的
Dependabot や開発者の環境が、package.json の `pnpm` フィールドを読まない新しい pnpm で lockfile を再生成して `overrides:` を落とさないように、frontend の pnpm を 9.15.9 に固定する（Issue #38 の (a)）。

## 入力
- `frontend/package.json`（`pnpm.overrides` の置き場所）
- `frontend/pnpm-lock.yaml`（トップレベル `overrides:` を持つ。変えない）
- `.github/workflows/ci.yml`（`pnpm/action-setup` の `version: 9`）
- 計画票 `vault/plans/P-20261022-dependabot-pnpm-overrides.md` の「分割方針」（調査の結果）

## 成果物
- `frontend/package.json`（1ファイル。`packageManager` の1行を足すだけ）

## 受け入れ基準
- `grep -c '^  .packageManager.: .pnpm@9.15.9.,' frontend/package.json` が `1` になる
- `python3 -c 'print(__import__("json").load(open("frontend/package.json"))["packageManager"])'` の出力が `pnpm@9.15.9` になる（JSON として読める）
- `git diff --merge-base work/p-20261022-dependabot-pnpm-overrides --numstat -- frontend/package.json` の出力が、`1`・`0`・`frontend/package.json` をタブで区切った1行（1行追加・0行削除）になる（`pnpm.overrides` などほかの行を変えていない）
- `git diff --merge-base work/p-20261022-dependabot-pnpm-overrides --name-only` の出力に `frontend/package.json` が含まれ、`frontend/pnpm-lock.yaml` は含まれない
- `pnpm -C frontend install --frozen-lockfile --lockfile-only --ignore-scripts 2>&1 | tail -1` の出力が `Done in` で始まり `using pnpm v9.15.9` で終わる（pnpm が固定した版に切り替わり、lockfile の overrides と一致する）
- `npx -y prettier@3.9.9 --check frontend/package.json 2>&1 | tail -1` の出力が `All matched files use Prettier code style!` になる

## 決定済み
- 足す行は `  "packageManager": "pnpm@9.15.9",`（先頭は空白2つ、末尾はカンマ）。置き場所は `"private": true,` の行の直後（`"scripts"` の前）。ほかの行は変えない
- 版は `9.15.9`（pnpm 9 系の最新。`npm view pnpm dist-tags.latest-9` で確認済み）。`9` のような範囲指定は `packageManager` では使えないので完全な版で書く
- `frontend/pnpm-lock.yaml` は変えない。`packageManager` は lockfile の内容に影響しない（planner が scratch の複製で、追加後も `--frozen-lockfile` が通ることを確かめた）
- `.github/workflows/ci.yml` は変えない。`pnpm/action-setup` の `version: 9` はそのまま（リポジトリ直下に package.json が無いので、action-setup が `packageManager` と食い違いを検出することは無い）
- 受け入れ基準5行目は、実行環境の pnpm が 10 以降（`packageManager` を見て版を切り替える）であることを前提にする。この環境の pnpm は 10.28.0 で、planner が同じコマンドで `using pnpm v9.15.9` を確かめた。初回は pnpm 9.15.9 をレジストリから取得する。`--lockfile-only` なので `node_modules` は作られず、frozen なので lockfile も変わらない
- 受け入れ基準6行目の prettier は `frontend/.prettierrc` を読む。`node_modules` を作らずに確かめるため `npx -y prettier@3.9.9`（`frontend/package.json` の devDependencies と同じ版）を使う
- Dependabot が `packageManager` を見て pnpm の版を決めるかは、この環境では確かめられない。確認はマージ後に人が行う（計画票の「マージ後に人が行う作業」）
