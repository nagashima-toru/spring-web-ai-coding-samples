# T-02 Dependabot PR の lockfile を pnpm 9 で補正して push する workflow を追加する

## 目的
Dependabot の frontend の PR で `frontend/pnpm-lock.yaml` の overrides が落ちていた時に、CI 上で pnpm 9 で lockfile を再生成して PR のブランチに push し、CI を起動し直す（Issue #38 の (b)。手作業の再生成をなくす）。

## 入力
- `.github/workflows/ci.yml`（pnpm・Node.js のセットアップの書き方、`workflow_dispatch` を持つこと）
- `.github/workflows/dependabot-review.yml`（Dependabot の PR の判定条件・`permissions` の書き方・`run` での `env` の使い方）
- `.github/dependabot.yml`
- 計画票 `vault/plans/P-20261022-dependabot-pnpm-overrides.md` の「分割方針」（調査の結果）

## 成果物
- `.github/workflows/dependabot-lockfile.yml`（新規1ファイル）

## 決定済み
- workflow の `name` は `Dependabot lockfile 補正`。ファイル先頭に、ほかの workflow と同じく日本語の1行コメントで目的を書く
- トリガは `on.pull_request` で、`types: [opened, synchronize, reopened]`、`paths` は `frontend/package.json` と `frontend/pnpm-lock.yaml` の2つ（この順）
- トップレベルは `permissions: {}`。ジョブ ID は `repair-lockfile` で、ジョブの `permissions` は `contents: write`・`actions: write` の順の2つ（`actions: write` は `gh workflow run` のため）
- ジョブの `if` は `github.event.pull_request.user.login == 'dependabot[bot]' && github.actor == 'dependabot[bot]'`（Dependabot 自身の push の時だけ動く。人や workflow の push では動かず、補正のコミットで自分を呼び直す循環も起きない）
- ジョブは `runs-on: ubuntu-latest`・`timeout-minutes: 10`
- 手順（各 step に日本語の `name` を付ける）：
  1. `actions/checkout@v7` を `ref: ${{ github.head_ref }}`・`persist-credentials: false` で使う（依存の解決中に書き込みの資格情報を置かない）
  2. `pnpm/action-setup@v6` を `version: 9` で使う（`.github/workflows/ci.yml` と同じ）
  3. `actions/setup-node@v7` を `node-version: '24'` で使う（cache は使わない）
  4. 検査（`id: check`、`working-directory: frontend`）：`pnpm install --frozen-lockfile --lockfile-only --ignore-scripts` が成功すれば `repair=false`、失敗すれば `repair=true` を `$GITHUB_OUTPUT` に書く。どちらでも step 自体は成功させる
  5. 再生成（`if: steps.check.outputs.repair == 'true'`、`working-directory: frontend`）：`pnpm install --lockfile-only --ignore-scripts`
  6. コミットと push と CI の起動（同じ `if`）：`git config user.name 'github-actions[bot]'`・`git config user.email '41898282+github-actions[bot]@users.noreply.github.com'` の後、`frontend/pnpm-lock.yaml` だけを add してコミットする。コミットメッセージは `chore(deps): pnpm 9 で pnpm-lock.yaml を再生成して overrides を復元する`。push は `https://x-access-token:${GH_TOKEN}@github.com/${GITHUB_REPOSITORY}.git` へ `HEAD:${HEAD_REF}` で行う。その後 `gh workflow run ci.yml --ref "$HEAD_REF"` で CI を起動する
- `run` の中に `${{ ... }}` を直接書かない（ブランチ名などによるスクリプトの注入を避ける）。`github.head_ref`・`github.token` は step の `env` で `HEAD_REF`・`GH_TOKEN` に渡して使う。`with` と `if` の中の式はよい
- `--ignore-scripts` を付けるのは、書き込みの権限を持つジョブで依存のライフサイクルスクリプトを動かさないため。`--lockfile-only` なので `node_modules` も作らない
- CI を `gh workflow run` で起動し直す理由：`GITHUB_TOKEN` で push したコミットは新しい workflow を起動しない（GitHub の仕様）が、`workflow_dispatch` は例外として起動できる。`.github/workflows/ci.yml` は `workflow_dispatch` を持つので変えない
- 補正のコミットの後に人が `@dependabot rebase` すると補正は消えるが、Dependabot の push でこの workflow がまた動いて補正し直す。対応は不要
- PR へのコメントやラベルは付けない（コミットメッセージで分かる）
- `.github/workflows/ci.yml`・`.github/workflows/dependabot-review.yml`・`.github/dependabot.yml` は変えない
- 受け入れ基準6行目の再現は、`/tmp/claude/P-20261022-dependabot-pnpm-overrides-T-02/` を `mkdir -p` で作り直し、そこへ `frontend/package.json` と `frontend/pnpm-lock.yaml` を複製し、lockfile のトップレベルの `overrides:` ブロック（`overrides:` の行から `importers:` の行の前まで）を消してから、手順4と手順5のコマンドを pnpm 9 で実行して行う（T-01 の `packageManager` がまだ無い時は `npx -y pnpm@9.15.9 ...` で pnpm 9 を使う）。一時ディレクトリは消さない。リポジトリ内のファイルは変えない
- GitHub Actions 上での実行・必須チェックの扱いは、この環境では確かめられない。actionlint などの外部ツールは使わず、YAML の解析結果（受け入れ基準1〜4行目）で構造を確かめる。実地の確認はマージ後に人が行う（計画票の「マージ後に人が行う作業」）
