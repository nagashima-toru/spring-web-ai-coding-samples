## 決定済み
- §3.1 の「**自動マージされない場合**」の箇条の後、「**人が行う設定（この順で行う）**」の前に、太字の小見出し `**lockfile の overrides の補正**` を1つ足す（§3.1 の既存の小見出しと同じ太字の書き方。`#` の見出しは足さない）。文字列 `lockfile の overrides の補正` はこの小見出しの1か所だけに書き、§6 の行など他の場所には書かない
- 小見出しの下に書くこと：
  - 事象：Dependabot が再生成した `frontend/pnpm-lock.yaml` からトップレベルの `overrides:` が消え、CI の `pnpm install --frozen-lockfile` が失敗する（Issue #38）
  - 原因（推定）：`packageManager` が無い時、Dependabot は package.json の `pnpm` フィールドを読まない新しい pnpm（pnpm 12 で確認）で lockfile を再生成する。Dependabot 側の版は確認できていないので「推定」と書く
  - 防ぐ仕組み：`frontend/package.json` の `packageManager` で pnpm を 9.15.9 に固定している（CI の `pnpm/action-setup` の `version: 9` と合わせる）
  - 自動補正：`.github/workflows/dependabot-lockfile.yml` が、Dependabot の push の時に pnpm 9 で frozen の検査をし、失敗したら lockfile を再生成してコミットし、PR のブランチに push して `gh workflow run` で CI を起動し直す。`GITHUB_TOKEN` の push は新しい workflow を起動しないため CI を明示的に起動すること、`--ignore-scripts` で依存のスクリプトを動かさないことを書く
  - 限界：起動し直した CI が PR の必須チェックとして扱われない時は、PR を閉じて開き直す（`pull_request` の `reopened` で CI が動く）。文字列 `PR を閉じて開き直す` をそのまま書く
  - 手作業の手順（自動補正が動かない・失敗した時）：bash のコードブロックで、PR のブランチを取得して切り替え、`frontend/` で `pnpm --version` が `9.15.9` であることを確かめ、`pnpm install --lockfile-only --ignore-scripts` で再生成し、`pnpm install --frozen-lockfile --lockfile-only --ignore-scripts` で確かめ、`pnpm-lock.yaml` だけをコミットして push する。pnpm 10 以降は `packageManager` を見て 9.15.9 に切り替わることを1行で添える
  - `@dependabot rebase` をすると補正のコミットは消えるが、自動補正がまた動くこと
- §6 の表の最後に1行足す：1列目は `` frontend の `pnpm install --frozen-lockfile` が `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` で失敗 ``（内側のバッククォートも付けてこのとおり）、2列目は「lockfile の overrides が落ちている。§3.1 の手作業の手順で pnpm 9 で再生成してコミットする」の趣旨（`lockfile の overrides の補正` の文字列は使わない）
- §1.1 の前提ツールの表・README.md・`docs/architecture.md` は変えない（`corepack enable` は `packageManager` に従うので §1.1 の記述は正しいまま。architecture.md は依存更新の運用を扱っていない）
- `docs/development-guide.md` は smoke の `(ref-1)` の対象の文書ではないので、`(ref-1)` の基準は置かない
- 文体は既存の §3.1 に合わせる（である調、箇条書き中心）
