# T-04 計画の差分が `/code-review` を通過する

## 目的
計画全体の差分（`packageManager` の固定・lockfile 補正の workflow・開発ガイドの追記）を `/code-review` で確かめ、致命的な指摘を直す。

## 入力
- 計画全体の差分：`git -C <worktree のパス> diff --merge-base <ベースブランチ>`
- `vault/tasks/P-20261022-dependabot-pnpm-overrides/T-01.md`〜`T-03.md`（各タスクの「決定済み」）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節

## 成果物
- 主な成果物は計画の差分への修正（致命的な指摘が無ければ変更なし）。直してよいファイルは次のとおり
- `frontend/package.json`
- `.github/workflows/dependabot-lockfile.yml`
- `docs/development-guide.md`

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない
- `pnpm -C frontend install --frozen-lockfile --lockfile-only --ignore-scripts 2>&1 | tail -1` の出力が `Done in` で始まり `using pnpm v9.15.9` で終わる
- `python3 -c 'print(__import__("yaml").safe_load(open(".github/workflows/dependabot-lockfile.yml"))["jobs"]["repair-lockfile"]["if"])'` の出力が `github.event.pull_request.user.login == 'dependabot[bot]' && github.actor == 'dependabot[bot]'` の1行になる
- `python3 -c 'print((lambda r: ([c in r for c in ("pnpm install --frozen-lockfile --lockfile-only --ignore-scripts", "pnpm install --lockfile-only --ignore-scripts", "gh workflow run ci.yml")], chr(36) + "{{" in r))(" ".join(x.get("run", "") for x in __import__("yaml").safe_load(open(".github/workflows/dependabot-lockfile.yml"))["jobs"]["repair-lockfile"]["steps"])))'` の出力が `([True, True, True], False)` になる
- `npx -y prettier@3.9.9 --check frontend/package.json 2>&1 | tail -1` の出力が `All matched files use Prettier code style!` になる
- `grep -c 'LOCKFILE_CONFIG_MISMATCH. で失敗' docs/development-guide.md` が `1` になる

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md` の「コードレビューを参照する基準がある時」と `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」の節に従う
- workflow の観点で致命的とみなすもの：`run` の中への `${{ ... }}` の直接の展開（スクリプトの注入）、書き込みの資格情報を残したまま依存を解決すること（checkout の `persist-credentials` が真、`--ignore-scripts` が無い）、Dependabot 以外の push でも動く `if`。これらは T-02 の「決定済み」に反するので直す
- 修正は T-01〜T-03 の「決定済み」に沿う範囲に限る。設計を変える修正（トークンの種類の変更、`.github/workflows/ci.yml` の変更など）はせず、「進捗」に書いて verifier に渡す
- 受け入れ基準2行目は、実行環境の pnpm が 10 以降で `packageManager` に従って 9.15.9 に切り替わる前提（T-01 と同じ）
